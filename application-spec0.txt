1. EXECUTIVE SUMMARY & ARCHITECTURAL OVERVIEW
--------------------------------------------------------------------------------
The To-Do Manager (TODO) is a multi-user task tracking application designed for
MVS 3.8j (TK5) running under Hercules. It implements a hybrid interface model
providing full-screen 3270 interactive access via KICKS, line-mode command-line
access via TSO CLIST, and automated overnight batch processing for archiving,
VSAM reorganization, and printed Daily Action Sheet distribution.

Core Design Principles:
- Upgrade-Safe Isolation: All user code, libraries, and VSAM datasets reside on
  user-preserved DASD (PUB000) under the TODO high-level qualifier (HLQ).
  System touchpoints (Master Catalog alias, SYS2.CMDPROC CLIST hooks) are
  isolated in an idempotent post-upgrade JCL job (INSTHOOK).
- Shared Business Logic: Record layouts (COPYLIB), validation rules (TODOVAL),
  and concurrency serialization (TODOLOCK) are shared across KICKS, TSO, and
  batch programs.
- Multi-User Concurrency: Because TK5 runs KICKS inside individual TSO address
  spaces rather than a single shared region, VSAM clusters use SHAREOPTIONS(3 3)
  protected by system-wide MVS ENQ/DEQ serialization (TODOLOCK) and optimistic
  record version counters.


2. USER INTERFACES & ACCESS MODES
--------------------------------------------------------------------------------
2.1 KICKS Online 3270 Interface (Transaction ID: TODO)
- Launched via custom CLIST (%TODOKICK) concatenating TODO.KICKS.LOADLIB and
  custom KICKS table suffixes (PPT=2$, PCT=2$, FCT=2$) without altering TK5
  system KICKS libraries.
- Pseudo-conversational COBOL programs driving 3270 BMS maps (TODOM00):
  * TODOM1 (Browse/List): View tasks filtered by Open/All/Waiting; page with
    PF7/PF8; inline row actions (S=Select/Edit, C=Complete, W=Waiting, X=Cancel);
    PF4=Add Task; PF9=User Settings; PF3=Exit.
  * TODOM2 (Detail/Add/Edit/Delegate): Create or modify tasks, assign/delegate
    to any valid TSO User ID, set status, priority, due date, category, and
    3x60-byte notes.
  * TODOM3 (User Settings): Toggle nightly Daily Action Sheet print flag (Y/N),
    set default priority (1-5), and update display name.

2.2 TSO Line-Mode CLI (%TODO CLIST -> TODOCMD)
- Invoked directly from TSO READY prompt without starting KICKS; opens VSAM
  clusters with DISP=SHR, executes requested action under ENQ/DEQ, outputs
  80-column formatted text to terminal, and frees allocations immediately.
- Supported Verbs (task IDs accept unpadded integers such as 12 -> 00000012):
  * TODO [LIST] [ALL|OPEN|WAIT] [USER(userid)]
  * TODO ADD 'title' [DUE(yyyymmdd)] [PRI(1-5)] [CAT(cat)] [TO(uid)] [NOTE('...')]
  * TODO VIEW taskid
  * TODO START taskid   (sets status to 'I')
  * TODO WAIT taskid    (sets status to 'W')
  * TODO DONE taskid    (sets status to 'C' and stamps DONE-DATE)
  * TODO CANCEL taskid  (sets status to 'X' and stamps DONE-DATE)
  * TODO ASSIGN taskid TO(userid)
  * TODO NOTE taskid 'text' [LINE(1|2|3)]
  * TODO PRINT [ON|OFF] [NAME('display name')] [PRI(1-5)]
- Note: Hard deletion is omitted from CLI; CANCEL ('X') marks tasks for the
  nightly audit archive run.

2.3 Nightly Batch Processing (TODO.JCL(TODONITE))
- Step 1 (Archive & Purge - TODOBAT1): Extracts all Completed ('C') and
  Cancelled ('X') tasks from TODO.MASTER.CLUSTER to a new +1 generation of
  TODO.ARCHIVE.GDG, then deletes extracted records from the master cluster.
- Step 2 (Reorganize - IDCAMS): Exports active records from TODO.MASTER.CLUSTER
  to a temporary sequential file, DELETEs and re-DEFINEs the master cluster and
  Alternate Index, reloads via REPRO, and rebuilds the index via BLDINDEX.
- Step 3 (Daily Action Sheet - TODOBAT2): Produces printed Action Sheets on
  SYSOUT=A (RECFM=FBA, LRECL=133) using Subscription Model C:
  * Default Mode: Scans TODO.CONTROL.CLUSTER and prints an Action Sheet for
    every user where CTRL-DAILY-PRINT-SW = 'Y'.
  * Override Mode: If SYSIN (e.g., TODO.PARMLIB(PRTLIST) or instream DD *)
    contains explicit TSO User IDs, prints exclusively for those users.
  * Output Format: All reports are written to a single JES2 spool dataset,
    separated by ASA '1' page-eject carriage controls with a prominent user
    banner header (USERID + Display Name) on each page for physical bursting.
  * Empty Queue Handling: If a subscribed user has zero active ('O','I','W')
    tasks, prints a 1-page banner sheet stating "NO OPEN TASKS TODAY".


3. MULTI-USER CONCURRENCY & SECURITY DESIGN
--------------------------------------------------------------------------------
- Dataset Allocation: All TSO, KICKS, and batch reporting jobs allocate VSAM
  clusters with DISP=SHR.
- System-Wide Serialization (TODOLOCK): S/370 Assembler subprogram callable by
  both OS/VS COBOL and KICKS COBOL. Issues MVS ENQ with SCOPE=SYSTEM on
  QNAME='TODOFILE' (RNAME='CONTROL ' for sequence number allocation;
  RNAME=TODO-OWNER-ID for task record updates) before READ-for-update, and
  DEQ immediately after WRITE/REWRITE/DELETE.
- Optimistic Locking: Master records carry a binary counter (TODO-REC-VERSION,
  PIC S9(4) COMP) verified before REWRITE to detect concurrent screen edits.
- Delegation Validation: Target TODO-OWNER-ID values are validated against
  TODO.CONTROL.CLUSTER (or valid TSO user registry) before reassignment.

6. RETURN CODE CONVENTIONS & DEVELOPMENT STANDARDS
--------------------------------------------------------------------------------
- Source Format: Columns 1-72 only (columns 73-80 blank for Git/card-reader
  compatibility); uppercase source throughout.
- Compiler Settings: IKFCBL00 invoked with PARM='LIB,APOST,DMAP,CLIST'.
- Standard Batch Return Codes:
  * RC = 00: Normal completion.
  * RC = 04: Warning (e.g., 0 tasks archived or empty print queue).
  * RC = 08: Recoverable data/parameter error (processing continues).
  * RC = 12: Severe I/O or VSAM status error (downstream steps bypassed).
